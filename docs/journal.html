commit 02/05 2026-08-12 23:49 JARVIS <jarvis@local>

Latence : JARVIS refusait de répondre sur la machine où il tourne

JARVIS mettait jusqu'à 15 secondes à répondre « je ne sais pas » à des questions simples sur sa propre machine, pendant que le HUD affichait déjà le CPU/RAM en direct via psutil.

APRÈS correctif : les mêmes 16 questions répondent toutes en moins de 90 ms, la plupart sous 3 ms.

Cause racine trouvée : la fonction de correspondance comparait le texte accentué (« mémoire vive ») à un texte non accentué (saisi ou transcrit vocalement) — donc jamais de correspondance, systématiquement le fallback lent vers le modèle IA. La fonction tools.contient() normalise désormais les deux côtés (accents retirés avant comparaison).

commit 03/05 2026-08-13 13:22 JARVIS <jarvis@local>

Une phrase pouvait figer JARVIS définitivement

La phrase « neuf puissance neuf puissance neuf puissance neuf » se traduisait en l'expression Python 9**9**9**9, que Python calcule sans jamais rendre la main (nombre à des milliards de chiffres) — blocage total après 15 secondes, processus tué.

Le code utilisait eval() avec un dictionnaire de fonctions autorisées (sqrt, pow, pi, e), documenté comme « dette technique : risque d'exécution de code arbitraire » — mais le vrai bug n'était PAS l'exécution de code arbitraire (le filtre en amont ne laissait passer que des chiffres et opérateurs mathématiques), c'était l'épuisement de ressources par un calcul légal mais absurdement grand.

Correctif : nouveau module calcul_sur.py qui parse l'expression en arbre syntaxique (AST Python) et borne la puissance AVANT de calculer, pas après. Mesures : calcul normal avant = 4 ms, la bombe = 9014 ms (part au modèle qui doit alors expliquer), calcul normal après = 3 ms. 37 contrôles de test dont 5 variantes de « bombe » toutes refusées en moins d'une milliseconde.

commit 04/05 2026-08-13 17:12 JARVIS <jarvis@local>

Catalogue des capacités : 16 entrées, adossées aux 142 points d'entrée réels

Besoin d'un catalogue des fonctionnalités de JARVIS consultable par deux systèmes différents (deux modes d'installation) sans divergence entre eux. Une liste écrite à la main diverge dès qu'une fonction est ajoutée sans que personne ne s'en aperçoive.

Solution : chaque capacité déclare les points d'entrée code qu'elle couvre, et une fonction verifier_coherence() compare cette déclaration au code réel — résultat : 142 points déclarés, 142 points réels dans le code, correspondance exacte.

Le contrôle a été éprouvé en retirant délibérément une capacité (vpn_connect) du catalogue : elle est ressortie comme « orpheline » dans le contrôle, prouvant que le test détecte vraiment les incohérences.

commit 05/05 2026-08-13 19:51 JARVIS <jarvis@local>

Linux : JARVIS s'installe et se charge sur Ubuntu 26.04

Première installation complète testée sur Linux nu (WSL2 Ubuntu 26.04) : 121 paquets installés, le fichier principal main2.py s'importe entièrement, 10 outils auto-découverts, 6 capacités sur 14 disponibles (les 7 absentes annoncent chacune pourquoi).

Quatre blocages trouvés en testant réellement : (1) des paquets Windows-only (pywin32, comtypes, pycaw) déclarés sans condition faisaient échouer pip entièrement ; (2) ensurepip est absent par défaut sur Debian/Ubuntu, l'installeur doit créer l'environnement virtuel puis s'amorcer lui-même ; (3) pygame sans version compilée pour Python 3.14 faisait échouer 48 autres paquets alors que tous ses imports étaient déjà protégés ; (4) le pire bug : sur Linux sans tkinter, « import pyautogui » lève SystemExit — qui n'hérite PAS de la classe Exception en Python — donc les blocs try/except Exception existants ne l'attrapaient pas du tout, le processus principal mourait silencieusement sans aucun message d'erreur ni trace.

Correctif : les fonctions d'import protégé attrapent désormais BaseException (en laissant explicitement passer KeyboardInterrupt).

version 1.2.0 2026-10-01 résumé de version, pas un commit

1.2.0 : plus de choses à distance, et tout ce qui est personnel devient une option éteinte

Le gros de la version : JARVIS se pilote depuis Discord (texte et vocal), prévient quand une tâche de fond se termine, met des tâches de côté pour la nuit, découpe une demande qui compare plusieurs choses, et confie une tâche de code à Claude Code, Codex, OpenCode, Cursor Agent ou OpenClaw — ou la fait lui-même dans un bac à sable limité au projet.

Deux corrections comptent plus que le reste. Lancé avec Windows par pythonw, JARVIS s'arrêtait en silence : pythonw n'a pas de sortie standard, et la première écriture le tuait. Et quand Gemini ne répond pas, il bascule sur un modèle Ollama local au lieu de se taire ; la liste des modèles est lue sur le serveur réel, pas devinée.

Domotique : il ne dit plus « c'est fait » quand Home Assistant a refusé l'action. C'est la règle du projet, enfreinte une fois de plus et corrigée.

Tout ce qui dépend d'une installation particulière (emploi du temps scolaire, révisions, détection de présence par webcam, carte OSINT) est livré désactivé, sans valeur par défaut tirée d'une vraie maison. On l'active dans l'installeur, rubrique Capacités.
