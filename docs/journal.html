commit 02/05 2026-08-12 23:49 JARVIS <jarvis@local>

Latence : JARVIS refusait de répondre sur la machine où il tourne

JARVIS mettait jusqu'à 15 secondes à répondre « je ne sais pas » à des questions simples sur sa propre machine, pendant que le HUD affichait déjà le CPU/RAM en direct via psutil.

APRÈS correctif : les mêmes 16 questions répondent toutes en moins de 90 ms, la plupart sous 3 ms.

Cause racine trouvée : la fonction de correspondance comparait le texte accentué (« mémoire vive ») à un texte non accentué (saisi ou transcrit vocalement) — donc jamais de correspondance, systématiquement le fallback lent vers le modèle IA. La fonction tools.contient() normalise désormais les deux côtés (accents retirés avant comparaison).

commit 03/05 2026-08-13 13:22 JARVIS <jarvis@local>

Une phrase pouvait figer JARVIS définitivement

La phrase « neuf puissance neuf puissance neuf puissance neuf » se traduisait en l'expression Python 9**9**9**9, que Python calcule sans jamais rendre la main (nombre à des milliards de chiffres) — blocage total après 15 secondes, processus tué.

Le code utilisait eval() avec un dictionnaire de fonctions autorisées (sqrt, pow, pi, e), documenté comme « dette technique : risque d'exécution de code arbitraire » — mais le vrai bug n'était PAS l'exécution de code arbitraire (le filtre en amont ne laissait passer que des chiffres et opérateurs mathématiques), c'était l'épuisement de ressources par un calcul légal mais absurdement grand.

Correctif : nouveau module calcul_sur.py qui parse l'expression en arbre syntaxique (AST Python) et borne la puissance AVANT de calculer, pas après. Mesures : calcul normal avant = 4 ms, la bombe = 9014 ms (part au modèle qui doit alors expliquer), calcul normal après = 3 ms. 37 contrôles de test dont 5 variantes de « bombe » toutes refusées en moins d'une milliseconde.

commit 04/05 2026-08-13 17:12 JARVIS <jarvis@local>

Catalogue des capacités : 16 entrées, adossées aux 142 points d'entrée réels

Besoin d'un catalogue des fonctionnalités de JARVIS consultable par deux systèmes différents (deux modes d'installation) sans divergence entre eux. Une liste écrite à la main diverge dès qu'une fonction est ajoutée sans que personne ne s'en aperçoive.

Solution : chaque capacité déclare les points d'entrée code qu'elle couvre, et une fonction verifier_coherence() compare cette déclaration au code réel — résultat : 142 points déclarés, 142 points réels dans le code, correspondance exacte.

Le contrôle a été éprouvé en retirant délibérément une capacité (vpn_connect) du catalogue : elle est ressortie comme « orpheline » dans le contrôle, prouvant que le test détecte vraiment les incohérences.

commit 05/05 2026-08-13 19:51 JARVIS <jarvis@local>

Linux : JARVIS s'installe et se charge sur Ubuntu 26.04

Première installation complète testée sur Linux nu (WSL2 Ubuntu 26.04) : 121 paquets installés, le fichier principal main2.py s'importe entièrement, 10 outils auto-découverts, 6 capacités sur 14 disponibles (les 7 absentes annoncent chacune pourquoi).

Quatre blocages trouvés en testant réellement : (1) des paquets Windows-only (pywin32, comtypes, pycaw) déclarés sans condition faisaient échouer pip entièrement ; (2) ensurepip est absent par défaut sur Debian/Ubuntu, l'installeur doit créer l'environnement virtuel puis s'amorcer lui-même ; (3) pygame sans version compilée pour Python 3.14 faisait échouer 48 autres paquets alors que tous ses imports étaient déjà protégés ; (4) le pire bug : sur Linux sans tkinter, « import pyautogui » lève SystemExit — qui n'hérite PAS de la classe Exception en Python — donc les blocs try/except Exception existants ne l'attrapaient pas du tout, le processus principal mourait silencieusement sans aucun message d'erreur ni trace.

Correctif : les fonctions d'import protégé attrapent désormais BaseException (en laissant explicitement passer KeyboardInterrupt).

1.2.0 : plus de choses à distance, et tout ce qui est personnel devient une option éteinte

Le gros de la version : JARVIS se pilote depuis Discord (texte et vocal), prévient quand une tâche de fond se termine, met des tâches de côté pour la nuit, découpe une demande qui compare plusieurs choses, et confie une tâche de code à Claude Code, Codex, OpenCode, Cursor Agent ou OpenClaw — ou la fait lui-même dans un bac à sable limité au projet.

version 1.3.0 2026-10-17 résumé de version, pas un commit

1.3.0 : JARVIS est livré avec son interface, et le projet parle six langues

Le dossier frontend/ contient désormais le HUD que l'auteur utilise tous les jours : une orbe 3D qui réagit à sa voix, le chat, l'état de la machine et un data center à onglets — tâches, compétences, mémoire, planning, médias, quotidien, maison, sécurité, réglages, contrôles, agents et système. L'onglet Agents liste les outils d'IA trouvés sur la machine et lesquels tournent. Il marche aussi sur téléphone, depuis le navigateur.

Jusqu'ici, l'interface ne démarrait jamais chez qui n'avait pas lancé install.bat : l'installeur .exe n'installait que les paquets Python. Au premier lancement, JARVIS lance maintenant npm install dans frontend/ tout seul, en une à deux minutes, si Node.js est présent. Sans Node.js, il marche toujours à la voix et dit que l'interface est indisponible.

L'interface est construite sur openclaw-jarvis-ui de JincocoDev (licence ISC, conservée dans frontend/LICENSE), lui-même basé sur le Three.js Orb Visualizer de Filip Zrnzevic, et rebranchée pour parler directement à JARVIS.

version 1.4.0 2026-11-07 résumé de version, pas un commit

1.4.0 : JARVIS t'entend mieux, répond plus vite, et peut être ton professeur

Le Mode Professeur : « interroge-moi sur Pythagore », « fais-moi un cours sur le réalisme ». JARVIS écrit un quiz ou un petit cours sur n'importe quel sujet, pose les questions une par une, donne un indice, répète. Les questions ratées deviennent des cartes mémoire qui reviennent deux jours plus tard, puis cinq. Avec Pronote, « fais-moi réviser » prépare le quiz de la prochaine évaluation en une vingtaine de secondes avec le modèle en ligne, au lieu de deux à quatre minutes avec le modèle local, qui reste le secours.

L'écoute tourne dans son propre processus (oreille.py) : Silero découpe les phrases après une demi-seconde de silence, Google les transcrit, et Parakeet prend le relais sur l'ordinateur quand Internet est coupé. On peut couper la parole à JARVIS (« stop », « attends », « Jarvis ») pendant qu'il parle. La première phrase d'une réponse parlée part pendant que la suite s'écrit encore.

Il tutoie, abandonne les formules de robot, et la réponse vide d'un modèle en panne n'entre plus dans la conversation. Le Mode Professeur est inspiré de celui du JARVIS 10.6 de TechEnClair.

version 1.4.1 2026-11-07 résumé de version, pas un commit

1.4.1 : le contrôle du micro ne peut plus faire planter JARVIS

Toutes les cinq minutes, la 1.4.0 vérifiait si le micro était coupé dans Windows. Ce contrôle lisait les périphériques audio dans JARVIS lui-même : ouvrir puis fermer PyAudio à cet endroit refermait le COM de Windows alors que des objets audio vivaient encore. Quand l'un d'eux était libéré plus tard, JARVIS plantait — violation d'accès 0xc0000005 dans _ctypes — parfois au bout de vingt minutes, parfois de plusieurs heures.

Correctif : le contrôle tourne dans un processus à part, lit PyAudio avant tout objet COM et ne referme jamais COM à la main. Même si un pilote audio se comporte mal, seul ce petit processus peut échouer : JARVIS reste debout.

version 1.5.0 2026-11-12 résumé de version, pas un commit

1.5.0 : l'Orbe de verre

Une nouvelle vue de JARVIS, calme, pour tous les jours : frontend/verre.html. L'orbe au milieu, ce que vous avez dit au-dessus, la réponse de JARVIS en dessous. Claire le jour (de 7 h à 20 h), sombre la nuit, ou forcée avec le bouton du coin ; sur ordinateur comme sur téléphone. Un bouton micro permet de parler tout de suite, sans dire « Jarvis ». C'est la page que vous regardez en ce moment qui lui ressemble.

Des cartes de verre apparaissent autour de l'orbe quand on en parle, et repartent seules au bout de 90 secondes. Sans réglage, rien ne change : le tableau de bord complet s'ouvre comme avant. Pour ouvrir l'Orbe par défaut, il faut écrire "interface_page": "verre.html" dans jarvis_config.json.

version 1.5.1 2026-11-12 résumé de version, pas un commit

1.5.1 : JARVIS ne lit plus les faux appels d'outil

Certains modèles répondaient à une question comme « quelle musique joue ? » par un texte inutilisable, <dots_function_call> invoke name="voir_ecran"…, au lieu d'une réponse. JARVIS le lisait à voix haute, l'affichait, et le gardait dans sa mémoire de conversation, où il devenait un exemple que le modèle recopiait. Ce texte demandait en plus à JARVIS de « regarder l'écran », une action qu'il utilise pour cliquer.

Maintenant ce texte n'est jamais dit, jamais affiché, jamais exécuté et jamais gardé en mémoire. S'il formait toute la réponse, JARVIS redemande une vraie réponse au modèle ; les anciennes entrées sont nettoyées au rechargement de l'historique.

L'Orbe de verre gagne son halo, une lueur plus forte quand JARVIS écoute ou parle, et sa ligne de voix. La carte Appareils n'affiche plus que ce qui est allumé, une ligne par appareil : un vrai Home Assistant comptait une trentaine de lecteurs, beaucoup éteints ou en double. Le site et le README montrent maintenant l'Orbe de verre.
